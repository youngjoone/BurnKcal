# 기기 저장

- iPhone: `expo-sqlite`의 `burnkcal.db`, schema `user_version=1`.
- 웹 미리보기: `database.web.ts`의 localStorage. iPhone DB와 동기화하지 않습니다.
- `entries(key TEXT PRIMARY KEY, value TEXT)`에 레코드별 JSON을 원자적으로 저장합니다.
- `meal.<id>`: 생성 시각(UTC timestamp), 사용자가 선택한 식사 날짜(기본값: 기기 현지 오늘), 제목, 확정 음식 목록, 삭제 시각.
- 같은 분석 결과는 같은 id로 `INSERT OR IGNORE`하여 재시도 시 중복 저장하지 않습니다.
- 수정은 한 레코드를 교체합니다. 삭제는 삭제 시각을 남기고 합계에서 제외하며 되돌릴 수 있습니다.
- 총합은 저장값을 누적 차감하지 않고 유효한 음식 목록에서 다시 계산합니다.
- 생성 시각과 식사 날짜는 별개입니다. 달력에서 과거 날짜를 선택해 사진 또는 직접 입력으로 기록할 수 있고, 미래 날짜 저장은 막습니다.
- 월별 달력의 점은 유효한 기록 유무를 표시하며 선택 날짜의 합계만 보여줍니다. 과거 기록을 추가해도 오늘 합계는 바뀌지 않습니다.
- 삭제 기록은 선택 날짜의 삭제 목록에서 재실행 후에도 복구할 수 있습니다.
- 날짜 변경·앱 복귀 때 오늘 날짜를 갱신합니다. 과거 기록은 저장한 지역 날짜를 유지합니다.
- 데이터가 손상되거나 DB 버전이 더 높으면 오류를 알리고 임의로 초기화하지 않습니다.
- 키·사진·설명 원문은 저장하지 않습니다. 사진은 분석 시 사용한 캐시만 존재합니다.
- 앱 삭제·브라우저 저장소 삭제·기기 분실 시 기록을 잃을 수 있습니다. 로그인·백업·동기화는 미구현입니다.
- SQLite는 앱의 저장 영역을 사용하며 별도의 DB 암호화는 아직 적용하지 않았습니다.

`profile` 키에는 신체 정보와 자동 계산 대상 여부를 저장합니다. 하루 목표는 읽을 때 검증된 입력에서 계산합니다.

`preferences` 키에는 제외 식재료·알레르기 선택과 가능한 조리 시간을 저장합니다. 프로필과 추천 설정은 서버로 전송하지 않습니다.
