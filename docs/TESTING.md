# 검증 기준

## 자동 검증

최초 한 번 `cd mobile && npm ci`를 실행한 뒤 저장소 루트에서:

```sh
./scripts/check.sh
```

스크립트는 서버 API 테스트 → 모바일 타입·응답 계약·포맷 검사 → iOS/웹 JS 번들 생성을 실행합니다.
GitHub Actions도 같은 명령을 실행합니다. 번들 생성은 Xcode 네이티브 빌드·시뮬레이터 검증과 다릅니다.

| 검증 | 확인하는 실패 유형 |
| --- | --- |
| `AnalysisApiTests` | 사진 누락·빈 파일·위장 이미지·MIME·설명 길이·CORS·데모 규약 |
| `GeminiFoodAnalyzerTests` | 모의 AI 서버로 전송 규약·다중 음식 합계·음식 아님·잘못된 JSON/숫자·인증/한도 오류 검증 |
| `mobile/tests/analysis.test.ts` | 누락된 모드·잘못된 타입·음수/비정상 칼로리·역전된 범위 |
| `mobile/tests/food.test.ts` | 음식 입력·양 보정·합계 재계산 |
| `mobile/tests/journal.test.ts` | 날짜별 집계·삭제 제외·손상된 기록 거부 |
| `mobile/tests/dates.test.ts` | 윤년·잘못된 날짜·요일 정렬·월말/연도 경계·미래 제한 |
| `mobile/tests/profile.test.ts` | 신체 입력 검증·목표 계산·자동 계산 제외 |
| `mobile/tests/recommendations.test.ts` | 잔여량에 따른 추천·작은 끼니 방지·제외 조건 유지 |
| `npm run typecheck` | 화면·서비스 사이 타입 불일치 |
| `npm run format:check` | 코드 포맷 차이 |
| Expo export | iOS/웹 모듈 해석·번들 오류 |

실제 멀티파트 용량 제한은 MockMvc가 아닌 실행 중인 서버에 5MB 초과 파일을 보내 413을 확인합니다.

## UI 수동 확인

- 첫 실행 프로필 3단계 → 저장 → Today. 재실행 후 재입력 없음, Settings에서 변경 가능
- Today → 촬영/앨범 선택 → 사진 확인 → 설명 입력 → 결과 → 음식 수정 → 확정 저장
- 기록 → 달력 날짜 선택 → 과거 날짜에 사진/직접 기록 → 해당 날짜 합계·표시 갱신
- 과거 기록 추가 후 오늘 합계 유지, 미래 날짜 비활성화, 월/연도 경계 이동
- 수정·삭제·복구 후 합계·추천 재계산. 삭제한 기록은 재실행 후에도 복구 가능
- 사진 선택 취소 시 출발 화면 유지, 이전 결과가 새 사진에 섞이지 않음
- 서버 중단 상태에서 오류 표시, 사진·설명 유지, 재시도 가능
- 분석 중 중복 탭 방지, 결과까지 스크롤 위치 초기화
- 데모에서는 예시 안내, 실제 AI에서는 사진·설명의 Gemini 전송 안내와 추정값 안내
- 서버 모드 변경 시 전송 안내를 갱신하고 재확인 후 분석
- 작은 화면, 스크롤, 키보드 노출 시 버튼 접근 가능
- 실제 아이폰에서 권한 거부·촬영·HEIC 사진·가로 세로 사진·Wi-Fi 연결

UI 변경은 브라우저 또는 Simulator에서 실제 렌더링을 봅니다. 가능한 환경과 확인하지 못한 환경을 구분해 보고합니다.

## 의존성 점검

`npx expo-doctor`로 Expo SDK 호환성을 확인합니다. 필요할 때 `npm audit`를 확인하되 SDK를 파괴하는 `--force` 변경은 하지 않습니다.
초기 설치(2026-09-12)에서 Expo의 빌드 도구 의존성 `xcode → uuid` 관련 moderate 경고가 보고됐습니다.
이는 Mac에 설치한 Xcode 앱의 평점이나 설치 상태와 관계없는 npm 패키지입니다.
SDK 호환성을 유지한 채 상위 패키지 수정 여부를 추적합니다.

## 2026-09-13 수동 검증 결과

실제 사용자 신체 정보 대신 가상의 검증용 프로필을 사용했습니다. 사진은 [공개 샘플](AI_SMOKE_TEST.md)입니다.

- iPhone 17 Pro / iOS 26.5 Simulator, Expo Go: 앨범 선택 → JPEG → 실제 Gemini 다중 음식 응답 → 음식 양 수정 → SQLite 저장 확인.
- 저장된 식사에서 한 항목의 양을 절반으로 변경하여 총합 1,170 → 845 kcal, 목표 1,650에서 잔여 805 kcal로 갱신 확인.
- 첫 프로필 등록 후 앱을 종료·재실행했을 때 바로 Today를 표시하고 목표·기록을 유지함.
- 달력의 7열 정렬, 미래 날짜 비활성화, 과거 날짜 직접 기록(150 kcal) 저장 확인. 오늘 합계는 845 kcal로 유지됨.
- 과거 기록 삭제 시 해당 날짜 합계 0, 앱 종료·재실행 → 삭제 내역에서 복구 시 150 kcal로 회복 확인.
- 웹: 프로필 등록, 모바일 폭의 UI, 추천 조건 저장·후보 없음 처리·레시피 상세를 확인.

실제 아이폰 카메라·권한·HEIC·Wi-Fi 접근, Android 실기기, TestFlight/독립 앱 빌드는 아직 검증하지 않았습니다. 현재 Simulator와 웹에 보이는 프로필·식사 값은 개발 검증용 예시입니다.
