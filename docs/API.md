# API 규약

기준 서버: `http://localhost:8080`. 아이폰에서는 Mac의 내부 IP로 바꿉니다.

## GET /api/health

```json
{ "status": "ok", "service": "burnkcal", "analysisMode": "demo" }
```

## POST /api/analyze

`multipart/form-data` 요청. 앱 런타임이 boundary를 생성하므로 Content-Type을 수동으로 고정하지 않습니다.

| 필드 | 필수 | 규칙 |
| --- | --- | --- |
| `image` | 예 | JPEG/PNG, 5MB 이하, 1,600만 화소 이하. 실제 이미지 디코딩 가능해야 함 |
| `note` | 아니오 | 기본 빈 문자열, 최대 300자. 서버에서 앞뒤 공백 제거 |

앱은 원본 사진을 긴 변 1,600px 이하 JPEG로 변환합니다.
서버 전체 multipart 요청 한도는 6MB입니다.

성공 응답은 HTTP 200입니다.

```json
{
  "mode": "demo",
  "title": "샘플 식사",
  "totalKcal": 650,
  "range": { "min": 500, "max": 800 },
  "items": [
    { "name": "밥", "portion": "1공기 (예시)", "kcal": 300 },
    { "name": "닭고기", "portion": "1인분 (예시)", "kcal": 250 },
    { "name": "반찬", "portion": "소량 (예시)", "kcal": 100 }
  ],
  "notices": [
    "AI 연결 전 데모입니다. 사진과 설명에 관계없이 같은 예시 결과를 반환합니다.",
    "표시된 칼로리와 범위는 화면 확인용이며 실제 음식의 영양 정보가 아닙니다."
  ]
}
```

- 기본 모드는 `demo`. 서버에서 Gemini를 설정하면 상태 API의 `analysisMode`와 결과의 `mode`가 `ai`입니다.
- 상태 API는 설정된 모드만 알려줍니다. 키 인증·모델 접근·한도는 실제 분석 요청에서 확인합니다.
- 각 음식은 `items`의 별도 항목이며 이름·추정량·칼로리를 갖습니다. 한 사진에서 여러 음식을 반환할 수 있습니다.
- 칼로리는 안전한 0 이상 정수이고 `min ≤ totalKcal ≤ max`여야 합니다.
- `totalKcal`은 각 `items[].kcal`의 합입니다. 서버에서 합산하고 앱에서도 일치 여부를 검증합니다.
- 데모의 범위는 UI 예시입니다. AI의 범위는 음식별 추정 범위를 서버가 합산한 값이며 통계적 신뢰구간이 아닙니다.
- 데모는 사진·설명을 해석하지 않습니다. AI는 음식 아님·판별 불가를 422로 처리합니다.
- AI 응답은 1~20개 음식, 음식별 0~10,000 kcal 정수와 범위 순서를 검증합니다. 실패를 0 kcal나 데모 성공으로 바꾸지 않습니다.

## POST /api/analyze/text

`application/json` 요청이며 사진 없이 음식 이름으로 추정합니다.

```json
{ "foodName": "순대국", "portion": "1인분" }
```

- `foodName`: 필수, 공백 제거 후 1~100자. `portion`: 선택, 최대 200자. 생략·빈 값이면 성인 1인분 기준입니다.
- 성공 응답은 사진 분석과 같은 `AnalysisResult`입니다. `mode`, 항목·합계·범위·안내 검증 규칙도 같습니다.
- Gemini는 음식명과 양을 해석합니다. 공인 DB에서 조회한 평균값이 아니며 공기밥·곁들임을 임의로 더하지 않도록 안내합니다. 양 가정과 한계는 `notices`에 표시합니다.
- 앱은 결과와 가정을 보여주고 사용자가 확인·수정한 뒤 저장합니다. 데모 응답은 저장하지 않습니다.
- 빈 이름·길이 초과·잘못된 JSON은 400, 음식이 아니거나 불명확하면 422입니다. 공급자 오류·시간 제한은 사진 분석과 같습니다.

## POST /api/recommendations

Gemini 모드에서 `application/json`으로 요청합니다. 신체 정보 원문은 보내지 않고 기기에서 계산한 목표·잔여량과 추천 조건만 보냅니다.

```json
{
  "dailyTargetKcal": 1650,
  "remainingKcal": 600,
  "preferences": {
    "allergens": ["달걀"],
    "excludedIngredients": "돼지고기",
    "maxMinutes": 30
  },
  "avoidNames": ["이전에 표시한 메뉴 이름"]
}
```

- 목표는 1,500~4,000 정수, 잔여량은 -4,000,000~목표 정수입니다. 잔여량은 저장된 오늘 식사에서 다시 계산합니다.
- 제외 항목은 달걀·우유·대두·밀·생선·갑각류·조개류·땅콩·견과류·참깨 중 최대 10개입니다. 추가 제외 문자열은 최대 200자, 쉼표/줄바꿈으로 구분합니다.
- 조리 시간은 15/30/60분 중 하나, `avoidNames`는 최대 3개 이름(각 1~100자)입니다. 현재 표시한 이름을 다음 생성에서 제외합니다. 유사한 메뉴까지 완전히 막지는 않습니다.
- 400 kcal 이상 잔여 시 한 끼 범위는 400~min(잔여, 700)입니다. 잔여가 400 미만이면 400~650 kcal의 한 끼를 제안하고 잔여 초과 가능성을 안내합니다. 이는 제품 정책이며 개인별 임상 기준이 아닙니다.

성공 응답(1~3개):

```json
{
  "mode": "ai",
  "recipes": [{
    "id": "server-generated-uuid",
    "source": "ai",
    "name": "닭가슴살 채소 덮밥",
    "minutes": 20,
    "allergens": ["대두", "밀"],
    "ingredients": [{ "name": "익힌 닭가슴살", "amount": "100g" }, { "name": "밥과 채소", "amount": "1인분" }],
    "steps": ["재료를 준비하고 충분히 익혀 주세요."],
    "nutrition": { "kcal": 500, "proteinG": 35, "carbsG": 60, "fatG": 13 }
  }],
  "notice": "프로필의 하루 목표·남은 칼로리·제외 재료·조리 시간을 반영해 새로 추천했어요."
}
```

위 JSON은 규약 설명용 축약 예시이며 완성된 조리법이 아닙니다. 실제 응답은 재료별 양·조리 순서를 제공합니다.

서버는 이름 100자, 재료 1~20개(이름/양 각각 100자), 단계 1~8개(각 500자), 조리 시간·열량 범위를 검사합니다. 탄단지는 유한한 0 이상 숫자(단백질≤150g, 탄수화물≤200g, 지방≤100g), 환산 열량과 차이는 max(80 kcal, 20%) 이내여야 합니다. 앱도 응답을 검증합니다. 이 검사는 실제 영양 정확도 평가를 대신하지 않습니다.

선택한 알레르기 표시·재료/단계의 알려진 관련 단어·추가 제외 단어가 있거나 이전과 같은 이름이면 후보에서 제외합니다. 성분표·교차 접촉·모든 동의어를 보장하지 않습니다. 입력 오류는 400, 맞는 후보 없음은 422, 응답 검증 실패는 502, 데모 모드는 503입니다. 공급자 한도/인증/시간 오류는 공통 규칙과 같습니다.

앱은 날짜·목표·잔여량·조건별 마지막 응답을 메모리에서 30분 재사용하고, 같은 진행 중 요청은 중복 전송하지 않습니다. 조건 변경 후 이전 응답은 표시하지 않습니다. **다른 메뉴 추천**은 새 요청입니다. 실패·로딩 때는 명시적인 기본 레시피 대체안을 보여주며 AI 성공으로 표시하지 않습니다.

## 입력 오류

| 상태 | 상황 |
| --- | --- |
| 400 | 사진 누락·빈 파일·손상된 이미지·화소 초과·설명 300자 초과 |
| 413 | 파일 5MB 또는 전체 요청 6MB 초과 |
| 415 | JPEG/PNG 외 파일 MIME |
| 422 | AI가 음식을 찾지 못했거나 구분하기 어려움 |
| 429 | AI 호출 한도 초과 |
| 502 | AI 연결·처리 실패 또는 응답 형식 오류 |
| 503 | AI 인증 문제 또는 요청 중단 |
| 504 | AI 요청 25초 초과 |

```json
{ "message": "사진을 선택해 주세요." }
```

위 입력 오류는 `ApiExceptionHandler`가 처리합니다. 잘못된 경로·메서드 등 프레임워크 오류는 별도 기본 형식일 수 있어 앱은 일반 오류 메시지로 처리합니다.
요청이 30초를 넘으면 앱이 취소하고 재시도를 안내합니다.

## 규약 변경 체크

Java `AnalysisResult`/`RecommendationResult` → TypeScript 타입/검증기 → 서버·앱 계약 테스트 → 이 문서를 같은 변경에서 갱신합니다.
