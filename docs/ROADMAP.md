# 구현 상태와 다음 단계

제품 방향과 경쟁 앱 대비 우선순위는 [PRODUCT_STRATEGY.md](PRODUCT_STRATEGY.md)를 기준으로 합니다.

## 1. 스켈레톤 — 구현

- Git ignore·작은 커밋·앱/서버 디렉터리 분리
- Expo 홈·사진 확인·결과 UI
- 사진 선택·JPEG 정규화·Java 서버 업로드
- 명시적인 데모 응답, 입력 검증·오류 처리
- 기능별 책임 문서, API 계약, 자동 검증과 CI

## 2. 기기에서 UI/UX 확인 — 진행

웹과 iOS JS 번들을 검증하고 Xcode 초기 설정 후 Simulator를 확인합니다.
실제 아이폰에서 촬영·권한·네트워크를 확인하고 버튼·레이아웃·문구를 조정합니다.

## 3. AI 연결 — 구현, 정확도 평가 진행

Gemini 3.1 Flash-Lite를 서버에서 호출합니다. `.env`의 키와 모델을 사용하며 기본 실행은 데모입니다.
2026-09-12 기준 표준 유료 요금: 입력 100만 토큰당 $0.25, 출력(추론 포함) $1.50.
사진당 고정 비용이 아니므로 실제 토큰 사용량을 기록해 평가해야 합니다.
[Google 가격표](https://ai.google.dev/gemini-api/docs/pricing#gemini-3.1-flash-lite)

- `FoodAnalyzer` 구현 추가, 서버 환경 변수로 키와 모델 지정
- JSON 구조와 숫자·합계 검증, 시간 초과·한도 초과·AI 실패 처리
- 비음식·불명확한 사진 처리, 설명 반영, 실제 분석과 데모 명확히 구분
- 한 사진에서 구분 가능한 음식을 각각 인식해 이름·추정량·칼로리 반환. 중복 집계 없이 항목 합으로 총합 계산
- 가려지거나 구분할 수 없는 음식은 확정하지 않고 불확실성 안내
- 음식과 양을 알고 있는 샘플로 정확도·지연·비용 비교
- 무료/유료 API의 데이터 사용 조건을 확인한 후 실제 사용자 사진 적용

공개 음식 사진 3장으로 실제 응답·다중 음식·합계 검증과 비음식 422 처리를 확인했습니다.
[실제 테스트 기록](AI_SMOKE_TEST.md)은 정확도 평가와 연결 검증을 구분합니다.

## 4. 실사용 최소 기능 — 계획, 미구현

- 음식별 이름·양 수정, 누락 추가·오인식 삭제, 총합 재계산
- 사용자 확인 후 기기에 식사 기록 저장, 수정·삭제
- 오늘 저장한 끼니와 칼로리 합계
- iPhone SQLite에 프로필·식사 기록 보관, 사진은 별도 파일 공간 사용
- 키·현재/목표 체중 외 나이·활동량 등을 고려한 하루 목표 설계
- 남은 칼로리와 식사 균형·알레르기·제외 음식을 고려한 메뉴/레시피 추천
- 과도하게 낮은 목표·끼니 제한을 자동 권장하지 않도록 기준 검토
- 중복 저장 방지, 수정·삭제 후 합계 재계산, 기기 현지 날짜 기준 집계

## 5. 차별화 가설 실험 — 계획, 미구현

- 한식 단위(밥 공기·반찬 양), 공유 음식 중 실제 먹은 양 빠른 보정
- 영향이 큰 불확실성만 선택 질문으로 확인
- 동의하에 기기에 자주 수정하는 음식·그릇 기준 기억

## 6. 필요할 때 확장 — 미구현

- 탄단지·영양 기준 DB 매칭·바코드·반복 식사
- 사용자별 호출 제한과 인증
- 외부 서버 배포·HTTPS
- 독립 iOS 빌드·TestFlight

현재 서버에는 외부 공개 운영을 위한 인증·호출 제한이 없습니다.
