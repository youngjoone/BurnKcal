# Gemini 실제 연결 검사

검사일: 2026-09-12. 모델: `gemini-3.1-flash-lite`.
서버에서 로컬 `.env`를 읽고 `/api/analyze`를 통해 Google Gemini를 호출했습니다.
키 값·사용자 사진·AI 원문은 저장소에 포함하지 않습니다. 아래 수치는 공개 샘플의 단일 실행 결과입니다.

## 공개 샘플 결과

| 사진 | HTTP | 응답 시간 | 추정 결과 |
| --- | --- | --- | --- |
| 피자·샐러드·빵 | 200 | 7.82초 | 3개 음식, 920 kcal (750–1,200) |
| 한식 상차림 | 200 | 4.30초 | 6개 음식, 1,125 kcal (930–1,370) |
| 루꼴라 토마토 피자 | 200 | 4.47초 | 1개 음식, 880 kcal (750–1,050) |
| Expo 아이콘, 음식 아님 | 422 | 3.88초 | 음식이 보이는 사진을 다시 선택하도록 안내 |

음식별 칼로리 합 = 총합, 범위 순서, `mode: ai`를 확인했습니다.
웹 앱의 앨범 선택 → JPEG 정규화 → 업로드 → 실제 결과 표시도 한식 샘플로 확인했습니다.
이 재분석은 6개 음식, 1,120 kcal (900–1,490)를 반환했습니다.

## 해석과 다음 수정

- 키 인증과 모델 접근, 사진 전송, JSON 처리, 앱 결과 표시는 정상입니다.
- 이 검사는 칼로리 정확도 검증이 아닙니다. 재료 중량과 실제 영양값을 모르는 공개 사진입니다.
- 피자·샐러드 사진에서 피자를 반 판으로 추정했습니다. 잘린 사진의 전체 양은 확인이 필요합니다.
- 같은 한식 사진에서 생선을 처음에는 연어 데리야끼, 재분석에서는 생선 조림으로 추정했습니다.
  보이지 않는 재료·조리법과 섭취량은 확정할 수 없습니다.
- 음식 이름·양 수정, 공유 음식 중 실제 먹은 양 확인을 기록 기능보다 앞서 구현해야 합니다.
- 측정 시간은 이 Mac과 네트워크의 소수 샘플 값이며 지연 보장이 아닙니다.
